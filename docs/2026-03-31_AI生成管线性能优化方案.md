# AI 生成管线性能优化方案

> 基于 Pretext 架构思想和当前系统瓶颈分析，制定分优先级的优化实施方案。

---

## 一、当前架构问题总览

### 请求处理流水线（WebSocket 路径）

```
用户消息 → A2UI事件 → 隐私检查 → 尽调强路由 → RAG路由
         → 意图检测 → 简单/复杂判断 → [需求分析LLM]
         → [Coordinator意图LLM] → [Agent执行LLM] → 伪流式推送
```

### 已识别瓶颈

| 编号 | 瓶颈 | 影响 | 严重度 |
|------|------|------|--------|
| B1 | 多 Agent 串行阻塞，完成后才伪流式推送 | 首 token 延迟极高（数十秒） | **P0** |
| B2 | 复杂消息 3 次串行 LLM 调用（需求分析→意图→执行） | 响应延迟叠加 | **P0** |
| B3 | LLM 配置每请求查数据库 | 不必要 I/O 延迟 | **P0** |
| B4 | 流式 Agent 不传对话历史 | 多轮对话质量差 | **P0** |
| B5 | 无动态 max_tokens 控制 | 简单问题冗长回复 | **P1** |
| B6 | Prompt 硬编码在代码中 | 无法快速迭代/A/B测试 | **P1** |
| B7 | WebSocket handler 500+ 行 | 难维护/测试 | **P2** |
| B8 | 尽调/RAG/隐私逻辑三重重复 | 修改一处需同步三处 | **P2** |

## 二、P0 优化：速度提升（直接影响用户感知）

### 2.1 LLM Config 内存缓存

**问题**：`BaseLegalAgent._load_llm_config()` 每次 WebSocket 消息都查数据库。

**方案**：添加带 TTL 的模块级缓存，配置变更频率极低（分钟级），缓存 60 秒即可。

```python
# backend/src/agents/base.py
import time

_llm_config_cache: dict = {"config": None, "expires_at": 0}
_LLM_CONFIG_CACHE_TTL = 60  # 秒

class BaseLegalAgent:
    async def _load_llm_config(self):
        now = time.time()
        if _llm_config_cache["config"] and now < _llm_config_cache["expires_at"]:
            return _llm_config_cache["config"]

        config = await self._fetch_from_db()
        _llm_config_cache["config"] = config
        _llm_config_cache["expires_at"] = now + _LLM_CONFIG_CACHE_TTL
        return config
```

**收益**：每次请求减少 1 次数据库查询（~5-20ms）。

### 2.2 合并意图识别 + 需求分析

**问题**：复杂消息走两次串行 LLM：需求分析 → 意图识别。

**方案**：合并为单次调用，一个 prompt 同时输出需求完整性判断和意图分类。

```
当前：需求分析(LLM, ~2s) → 意图识别(LLM, ~2s) → Agent执行(LLM)  = 首token ~6s+
优化：合并意图+需求(LLM, ~2s) → Agent执行(LLM)  = 首token ~4s+
进一步：关键词命中时(0ms) → 直接Agent执行  = 首token ~2s
```

**关键词快速路径覆盖率目标**：从当前 ~80% 提升到 ~90%（扩充法律领域关键词）。

### 2.3 真流式多 Agent 输出

**问题**：多 Agent DAG 执行完毕后，才将完整结果文本按 20ms 间隔分块推送（伪流式）。

**方案**：
1. DAG 中第一个 Agent 使用真流式（`stream_chat`），token-by-token 推送
2. 后续 Agent 结果以增量方式追加
3. 保留 `_stream_response_tokens` 仅作为非流式 Agent 的回退

```python
# 伪代码
async def execute_dag_streaming(agents, message, ws):
    first_agent = agents[0]
    # 第一个 Agent 立即流式输出
    async for token in first_agent.stream_chat(message):
        await ws.send_json({"type": "content_token", "content": token})

    # 后续 Agent 增量追加
    for agent in agents[1:]:
        result = await agent.chat(message, context=first_result)
        await ws.send_json({"type": "agent_result", "content": result})
```

**收益**：用户首 token 感知从"等待所有 Agent 完成"变为"第一个 Agent 开始输出即可见"。

### 2.4 WebSocket 路径补对话历史

**问题**：`stream_chat()` 只发送 system + 当前 user 消息，完全无多轮上下文。

**方案**：在 WebSocket handler 中，调用 Agent 前取最近 N 条对话历史，传入 messages 列表。

```python
# 在 websocket_chat 中，调用 Agent 前
recent_history = await chat_service.get_recent_messages(
    conversation_id=conversation_id,
    limit=10  # 最近 10 条
)
history_messages = [
    {"role": msg.role, "content": msg.content}
    for msg in recent_history
]

# 传入 Agent
result = await agent.chat(
    message=user_message,
    history=history_messages  # 新增参数
)
```

**收益**：多轮对话质量从"无上下文"提升到"有 10 轮上下文"。

## 三、P1 优化：质量提升

### 3.1 动态 max_tokens

**方案**：根据问题复杂度分档控制输出长度。

| 复杂度 | 判断条件 | max_tokens |
|--------|---------|------------|
| 简单 | 招呼语、是否类问题、<20字 | 256 |
| 中等 | 单一法律问题、概念解释 | 1024 |
| 复杂 | 多步骤分析、文书起草 | 4096 |
| 工作台 | 尽调报告、合同审查 | 8192 |

### 3.2 Prompt 模板化管理

**方案**：将散落在代码中的 prompt 统一到配置目录。

```
backend/src/prompts/
├── coordinator/
│   ├── intent_classification.txt
│   └── task_planning.txt
├── agents/
│   ├── contract_review.txt
│   ├── legal_consultation.txt
│   └── document_drafting.txt
└── system/
    ├── requirement_analysis.txt
    └── response_formatting.txt
```

支持：
- 版本管理（Git 追踪）
- 热更新（文件变更自动重载，无需重启）
- 变量插值（`{user_preference}`、`{conversation_context}`）

## 四、P2 优化：架构改善

### 4.1 拆分 WebSocket Handler

**当前**：`websocket_chat` 约 500 行，包含所有路由逻辑。

**方案**：策略模式拆分。

```python
# backend/src/api/routes/chat_handlers/
├── __init__.py          # ChatRouter 策略分发
├── a2ui_handler.py      # A2UI 事件处理
├── workspace_handler.py # 工作台交互
├── canvas_handler.py    # Canvas 编辑
├── privacy_handler.py   # 隐私检查 + PII 脱敏
├── due_diligence.py     # 尽调强路由
├── rag_handler.py       # 知识库 RAG
└── chat_handler.py      # 通用对话（意图→Agent→流式）
```

### 4.2 统一 Service 层

**当前**：尽调/RAG/隐私还原在 `chat_service.py`（同步+流式）和 `chat.py`（WebSocket）三重实现。

**方案**：统一到 Service 层，三个入口复用同一实现。

```python
class ChatOrchestrator:
    """统一编排层，被 HTTP/流式/WebSocket 三个入口共享"""

    async def process(self, message, context) -> ChatResult:
        # 1. 隐私检查
        message = await self.privacy_service.check(message, context)
        # 2. 路由决策
        route = await self.router.decide(message, context)
        # 3. 执行
        result = await route.handler.execute(message, context)
        # 4. 后处理
        return await self.postprocess(result, context)
```
