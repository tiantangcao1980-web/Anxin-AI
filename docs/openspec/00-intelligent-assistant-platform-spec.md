# OpenSpec — 全设备智能助手平台规范

> 日期：2026-05-08
> 状态：产品定位与平台能力规范
> 关系：本规范是 `01-commercial-delivery-spec.md` 的上层产品合同；商业交付门禁以该文件定义的能力为验收目标之一。

## 1. 平台使命

安心 AI 的长期定位是一个面向中小企业和专业服务方的全设备智能助手平台。它以桌面客户端为主要生产力工作站，以移动端/小程序为随身助手和远程控制入口，以 Web 管理端承载组织协作、运营和管理能力。

平台必须帮助中小企业处理日常经营中的法务、财务、税务、合规、舆情和办公风险；当事项进入高风险、高金额或强专业判断阶段时，系统必须把用户连接到可信赖的律师、律所、税务师、税务师事务所、财务顾问、会计/审计人员等专业服务方。

## 2. 用户与服务对象

| 对象 | 典型用户 | 关键场景 | 成功标准 |
|---|---|---|---|
| 企业需求方 | 中小企业老板、股东、高管、行政、人事、财务、法务/合规兼岗人员 | 合同审查、劳动人事、应收账款、税务咨询、工商事项、供应商/客户尽调、舆情预警、内部制度文档 | AI 先完成低成本处理，高风险事项明确转专业服务；记录、材料和依据可追溯 |
| 专业服务方 | 律师、律所、税务师、税务师事务所、财务顾问、会计/审计人员及机构 | 接收高质量线索、查看 AI 材料包、在线咨询、项目委托、服务评价、获客推广 | 资质可信、利益冲突可拦截、SLA 可衡量、线索归因和结算清晰 |
| 平台运营方 | 审核、风控、客服、内容/商业运营、管理员 | 资质审核、投诉处理、舆情处置、推广获客、证据链归档、发布验收 | 风控可审计、运营动作可回滚、商业证据不依赖 mock |

## 3. 平台能力合同

### 3.1 桌面主工作站

桌面客户端是未来重点端侧，必须支持：

- 可安装、可启动、可升级、可签名/公证验证的客户端交付。
- 本地加密库、系统 keyring、离线任务队列、失败重试和人工介入状态。
- 本地模型调用、本地知识库、本地文件分析、拖拽分析和长任务执行。
- 模型、知识库、Skills、MCP Server 和隐私模式的统一配置入口。
- 执行日志、工具调用日志、材料访问日志和本地/云端同步状态可审计。

### 3.2 移动随身助手与桌面远控

移动端不能只是通知壳，必须支持：

- 咨询、审批、通知、材料查看、消息、任务和跨设备会话继续。
- 与桌面客户端安全配对，显示设备状态、桌面任务和执行结果。
- 向桌面发送远程命令，包括启动任务、继续对话、分析文件、取消任务和确认高风险动作。
- 敏感动作二次确认、权限说明、撤销入口、失败状态和审计日志。
- 远控通道必须可禁用、可撤销、可过期，不能在用户不知情时静默执行。

### 3.3 任意模型、Skills 与 MCP

平台必须允许用户或组织配置：

- 云端模型、本地模型、自托管模型和 OpenAI-compatible endpoint。
- provider、endpoint、model、api key、上下文窗口、速率限制、隐私模式和组织 scope。
- Skills 能力包、MCP Server、工具白名单、参数权限和调用审计。
- 组织级禁用策略、最小权限授权、失败回滚和安全审查记录。

验收要求：更换模型或启用 Skills/MCP 后，不能绕过 RBAC、订阅、隐私模式、知识库权限或日志脱敏。

### 3.4 独立知识库与本地安全

知识库必须支持个人、组织、项目、客户和本地知识库分层：

- 每条知识必须有来源、版本、引用、权限、脱敏状态和删除策略。
- 本地/绝密模式可使用本地模型和本地知识库完成任务，数据默认不离开设备。
- 混合模式必须按隐私层级选择是否同步、是否调用云端模型、是否允许外部 MCP。
- 云端模式也必须保留最小权限、审计、引用和可导出证据链。

验收要求：本地/绝密模式下，云端模型调用、外部 MCP 调用、同步上传和远控外传默认 fail-closed；只有用户显式授权后才允许出站。

### 3.5 专业服务、舆情与获客

平台的商业价值来自企业侧风险处理和服务侧可信获客：

- 高风险事项必须生成转专业人士卡片，包含服务类型、风险摘要、材料包、授权范围和候选服务方。
- 舆情监测必须连接风险告警、处置建议、危机材料包和专业服务转介。
- 推广获客必须清楚标识广告/推荐属性，线索来源可追踪，用户授权可撤销，服务方不得绕过平台骚扰用户。
- 计费模型必须区分企业侧 AI 套餐、专业服务按次/项目计费和服务方获客/推广产品。

### 3.6 通用工作助手、软件开发与原型设计

参考 Hermes Agent、OpenClaw、HiClaw、DeepTutor、CLI-Anything、browser-use 等项目，本平台应从行业专用助手升级为可处理日常工作和管理问题的综合助手：

- 工作助手：会议纪要、制度问答、内部通知、报告生成、培训材料、任务拆解、日程提醒和周报/月报。
- 协作写作：支持多文档编辑、选区改写、知识库引用、版本对比和导出。
- 软件/原型工作台：允许用户生成内部小工具、流程原型、表单页面、数据处理脚本、CLI harness、设计原型和演示材料。
- 浏览器执行器：辅助用户在公开网站或企业系统中查询、截图、下载材料、填写草稿和形成操作记录。
- 自动化任务：支持自然语言创建定时巡检、数据采集、风险监测、报告生成和提醒。

验收要求：软件/原型、浏览器执行、CLI 工具和自动化任务默认只在沙盒或草稿态运行；凡涉及外部提交、生产数据、批量发送、代码执行、远程桌面控制和公开采集，必须进入审批和审计流程。

### 3.7 企业智能体治理

企业组织内的 AI 智能体不仅要能用、能解决问题，还要管得住、控得稳、风险可控。组织账号默认只开放基础能力；完整能力只开放给已订阅或已购买对应服务的组织，并且默认只有老板/Owner 和超级管理员可以配置或启用高风险能力。

| 角色 | 默认能力 | 可购买/订阅后开放 | 高风险限制 |
|---|---|---|---|
| 老板 / Owner | 全局风险、账单、服务转介、组织策略 | 全模型、全 Skills/MCP、浏览器执行、软件/原型工作台、桌面远控、自动化 | 外部提交、生产写入、批量导出仍需二次确认 |
| 超级管理员 | 成员、权限、知识库、模型和工具策略 | 能力市场、MCP、CLI、自动化、审计查询 | 不能关闭审计；导出全量数据需 Owner 授权 |
| 部门管理员 | 部门知识库、模板、流程和成员协作 | 部门级 Skills、低风险自动化、部门报表 | 跨部门/跨客户数据需额外授权 |
| 普通员工 | 基础问答、授权知识库、文档草稿、任务提醒 | 个人效率 Skills、低风险浏览器辅助 | 默认不能启用外部 MCP、远控桌面、执行代码或批量外发 |
| 外部专业服务方 | 授权材料包、项目沟通、专业意见提交 | 获客推广、项目协作空间 | 不得跨客户检索或下载未授权原始资料 |

智能体能力必须按风险分级管理：

- L0：只读问答、总结、解释，允许全员使用。
- L1：草稿生成，如合同草案、制度草案、代码片段、原型草图，必须标记“未审核”。
- L2：内部写入，如创建任务、写入知识库、修改内部文档，需要组织权限。
- L3：外部执行，如浏览器填报、发送邮件/消息、调用外部 MCP、公开网页采集，需要订阅、授权和审计。
- L4：高风险控制，如桌面远控、执行代码、财税法正式提交、批量导出，仅老板/超级管理员或临时授权人可用。
- L5：禁止或专项审批，如绕过访问控制、规避验证码/反爬、读取无授权数据、关闭审计，默认禁止。

验收要求：任何能力执行前必须经过 `subscription + role + permission + risk_level + privacy_mode + device_trust` 六层校验；失败必须 fail-closed，并输出可解释的拒绝原因。

### 3.8 协作式多智能体控制面

参考 HiClaw 的 Manager-Workers、Human-in-the-loop、声明式通信策略和 AI Gateway credential isolation，企业版需要建立“多智能体控制面”，而不是让每个 agent 自行持有工具和密钥。

| 控制面对象 | 定义 | 核心约束 |
|---|---|---|
| AgentManager | 组织级或项目级智能体协调者 | 可分派任务，但不能绕过组织策略、隐私模式和审批状态 |
| AgentTeam | 部门/项目/客户事项下的智能体组 | 有 Leader、成员、数据域、可见房间和工具范围 |
| AgentWorker | 具体执行单元，如法务审查、财务分析、浏览器执行、软件原型 | 只持有短期 consumer token，不持有真实 API key、PAT、财务/税务凭据 |
| HumanParticipant | 老板、超级管理员、部门管理员、员工、外部专业服务方 | 按层级进入房间、@ agent、审批、暂停、接管或终止任务 |
| ChannelPolicy | 会话/房间/项目中的通信和可见策略 | 控制谁能看、谁能说、谁能 @、谁能让 agent 执行动作 |
| CapabilityRoute | LLM/MCP/CLI/浏览器/采集器/远控等能力路由 | 按 `allowedConsumers` 授权，撤销不需要暴露或轮换真实密钥 |
| SharedArtifactStore | 任务材料、spec、结果、截图、日志和证据 | agent 边缘无状态，敏感材料进入对象存储并按权限读取 |

必须遵守：

- **真实密钥不进 agent**：LLM key、MCP token、GitHub PAT、财税接口 key、浏览器账号凭据都由网关/密钥服务托管；agent 只拿可撤销 consumer token。
- **房间可见与人类可介入**：高风险任务必须在可审计工作室中运行，老板/超级管理员可旁听、暂停、接管和终止。
- **声明式权限策略**：Agent、Team、Human、ChannelPolicy、CapabilityRoute 都应可声明、可审计、可回滚。
- **Leader 边界**：跨团队协作优先通过 Team Leader 汇总，Manager 不直接穿透每个 Worker 的私有上下文。
- **共享 artifact**：任务输入、阶段结果、审批意见、最终交付物和回滚材料都必须进入共享 artifact store，不允许只存在 agent 私有上下文中。

验收要求：至少覆盖“员工请求浏览器填表被拒绝”、“部门管理员创建部门报告 agent”、“老板批准桌面远控任务”、“超级管理员撤销 MCP route 后 agent 立即失权”、“外部专业服务方只能看授权材料包”五类权限回归。

### 3.9 可信会话体验、Skills 进化与智能体自我改进

平台交互需要借鉴 Codex 和 Claude 这类成熟 AI 工作台的可观察体验，而不是停留在普通聊天框。这里借鉴的是公开可见的产品交互原则，不复制任何私有提示词或内部实现。

必须具备的交互体验：

- **过程可见**：长任务要展示计划、当前步骤、工具调用状态、等待原因、失败原因和下一步，不让用户只看到“处理中”。
- **证据可点**：回答中的法规、合同、资料、网页、知识库和生成文件都应有引用、来源、版本和打开入口。
- **可打断可恢复**：用户可暂停、继续、取消、接管；跨设备继续时保留上下文、任务状态和未完成动作。
- **行动前确认**：外部提交、批量发送、付费、远控、执行代码、修改组织策略等动作必须在执行前展示影响范围和撤销方式。
- **结果可编辑**：合同、报告、原型、脚本、材料包和工作流应作为可编辑 artifact，而不是只以聊天文本存在。
- **低噪音高密度**：桌面端偏工作台，移动端偏随身助手，避免营销式大卡片和重复说明；关键按钮、状态和风险提示要一眼可扫。
- **命令与能力可发现**：模型、Skills、MCP、知识库、浏览器、CLI、桌面远控和专业服务转接应通过能力中心、命令面板或上下文建议被发现。

Skills 和智能体进化必须受治理：

- **Skill Lifecycle**：每个 Skill 有名称、版本、owner、能力范围、风险级别、输入输出 schema、依赖、评测集、变更记录和回滚版本。
- **Skill Evolution Proposal**：智能体可以基于失败案例、用户反馈和评测结果提出新 Skill 或改进建议，但默认只生成草案和测试，不直接改生产启用版本。
- **Eval Gate**：Skill 升级必须跑离线评测、权限回归、注入防护、隐私模式出站拦截和审计日志检查。
- **Human Approval**：组织级 Skill、外部 MCP、浏览器执行、CLI、桌面远控和专业服务转接相关 Skill 必须由老板/Owner 或超级管理员批准后启用。
- **Rollback & Audit**：每次启用、禁用、升级、降级、失败和越权拒绝都要写审计；发现风险时可以一键回滚到上一版本或禁用该 route。
- **Memory Governance**：个人记忆、组织记忆、客户项目记忆和 Skill 经验库必须分层，支持查看、删除、导出和过期策略。

验收要求：至少覆盖“长任务过程可见”、“生成报告作为 artifact 可编辑”、“用户中断后跨设备恢复”、“Skill 升级未评测被拒绝”、“Skill 通过评测但缺管理员批准被拒绝”、“高风险 Skill 回滚后下一次调用失权”六类回归。

## 4. 当前代码基础与缺口

已存在的基础：

- LLM/本地模型：`backend/src/services/llm_service.py`、`backend/src/services/private_llm_service.py`、`backend/src/api/routes/llm.py`、`desktop/src/commands/local_llm.rs`。
- MCP/Skills：`backend/src/mcp_server.py`、`backend/src/api/routes/mcp_routes.py`、`backend/src/services/mcp_client_service.py`、`backend/src/models/mcp_config.py`、`backend/src/services/skill_service.py`。
- 知识库：`backend/src/services/knowledge_management.py`、`backend/src/services/knowledge_service.py`、`backend/src/api/routes/knowledge.py`。
- 桌面同步/本地安全：SQLCipher/keyring、offline queue、sync_log、desktop security gate 已有代码级证据。
- 桌面绝密模式：CLI、同步冲突、Harness artifact、本地同步桥、统一 API fetch、WebView 全局 fetch 与 WebSocket 已补 TopSecret/local data-network guard；packaged runtime、CSP/外部脚本和 tauri-plugin-http scope 证据仍需补。
- 移动隐私上下文：移动端已有本地模型/LAN Ollama 语义基础。
- 外部参考分析：`docs/references/agentic-platform-benchmark-2026-05-08.md` 已整理可借鉴能力和风险边界，并纳入 HiClaw 的多智能体控制面、Human-in-the-loop、Gateway credential isolation 和声明式通信策略。

仍不能宣称完成的缺口：

- 桌面主工作站尚缺完整的模型/知识库/Skills/MCP 配置 UI 与 packaged runtime 验收。
- 移动远程控制桌面尚缺设备配对、远程命令、状态回传、撤销和审计闭环。
- 任意模型/Skills/MCP 的组织策略、权限拒绝、调用日志和隐私模式回归仍需补完整商业证据；当前 MCP 外部连接只完成了商业环境 fail-closed allowlist 基线。
- 通用工作助手、软件/原型工作台、浏览器执行器、CLI harness 和定时自动化尚缺统一产品入口、沙盒执行和企业审批。
- Codex/Claude 风格的可信会话体验尚缺完整产品化：长任务计划/进度/证据/可恢复状态、artifact 编辑、能力命令面板和跨设备接续仍需统一设计与验收。
- Skills 进化和智能体自我改进尚缺生命周期模型、评测门禁、审批、回滚和记忆治理。
- 企业智能体治理已补第一层 agent capability policy 决策引擎，覆盖未注册工具 fail-closed、订阅 feature、角色 permission、隐私模式、设备信任、通道策略和审批上下文；MCP 外部连接已补 stdio command/command-line/env allowlist、SSE scheme/host allowlist 和子进程最小环境；仍缺 CapabilityRoute/短期 route token、Human-in-the-loop 工作室、真实 approved MCP connector 演练和撤销后立即失权证据。
- 协作式多智能体控制面尚缺 AgentManager、AgentTeam、AgentWorker、HumanParticipant、ChannelPolicy、CapabilityRoute 和 SharedArtifactStore 的正式数据模型与审计闭环。
- 税务师、税务事务所、财务顾问、会计/审计人员等专业服务方仍处于规范预留和后续扩展阶段。
- 舆情监测到专业处置和服务方获客的商业闭环仍需产品与代码验收。

## 6. 发布门槛

任何商业交付候选版必须证明：

- 桌面、移动、小程序、Web 的关键路径都不依赖 mock/fallback 伪成功。
- 本地/绝密模式的数据出站被默认拦截，并有测试证明。
- 用户可配置模型、Skills、MCP 和知识库的路径有组织隔离、权限拒绝和调用审计。
- 移动远控桌面必须有设备配对、二次确认、撤销和审计证据。
- 通用工作助手、软件/原型工作台、浏览器执行器、CLI harness 和自动化任务必须有沙盒、审批、审计和回滚证据。
- 长任务、生成 artifact、跨设备继续、工具调用、失败恢复和用户接管必须有可观察交互证据。
- Skills 升级和智能体自我改进必须经过评测、审批、审计和可回滚版本控制，不允许直接自改生产能力。
- 企业组织默认只开放基础能力；完整能力必须受订阅、老板/Owner、超级管理员和角色权限控制。
- Agent/Worker 不得直接持有真实密钥；LLM、MCP、CLI、浏览器和第三方系统能力必须通过可撤销 consumer token 或等价网关策略访问。
- 高风险多智能体任务必须提供房间可见审计、人类介入、暂停、接管、终止和 artifact 留痕证据。
- 重大事项必须能转可信专业人士，并保留授权材料包。
- 舆情监测和推广获客不得绕过用户授权、广告标识、隐私脱敏和反骚扰规则。
