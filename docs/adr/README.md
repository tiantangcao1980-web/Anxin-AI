# 架构决策记录 (ADR)

> Architecture Decision Records
> 记录关键架构决策的**当时背景、考虑的方案、最终选择、影响**

## 为什么需要 ADR

- 决策的"为什么"会随时间被遗忘
- 新成员需要快速理解历史脉络
- 避免重复评估同一问题
- 提供变更决策的依据

## 模板

新 ADR 文件名：`NNN-decision-title.md`（如 `001-v3-merge-strategy.md`）

```markdown
# ADR-NNN: <决策标题>

> 日期：YYYY-MM-DD
> 状态：提议中 | 已采纳 | 已弃用 | 被 ADR-XXX 取代
> 决策人：<姓名/角色>

## 背景

为什么需要做这个决策？当前问题是什么？

## 考虑过的方案

### 方案 A
- 优点：
- 缺点：

### 方案 B
- 优点：
- 缺点：

## 决策

最终选择什么，为什么。

## 影响

- 正面影响：
- 负面影响：
- 后续行动：

## 参考

- 相关 issue / PR
- 相关讨论
```

## 何时写 ADR

| 必须写 | 不需要写 |
|---|---|
| 架构层选型（数据库、消息队列、AI provider） | 业务逻辑实现细节 |
| 跨域影响的设计模式 | 单一文件的代码重构 |
| 重大命名/目录调整 | 命名规范的小调整 |
| 安全策略变更 | 修 bug |
| 第三方依赖变更（添加 / 升级 major） | 依赖小版本升级 |
| 破坏性 API 变更 | API 兼容性扩展 |

## 维护

- ADR 一旦采纳，不再修改正文（追加变更走新 ADR）
- 状态字段及时更新
- 被取代的 ADR 必须指明取代者
