### 2.2 详细说明

#### A-1 前端设计系统统一

**目标**: 建立 Shadcn/UI + Radix + CSS 变量体系的统一设计系统

**关键交付物**:
- 全局 CSS 变量定义文件（`design-tokens.css`），覆盖颜色、间距、圆角、阴影、排版
- Shadcn/UI 主题配置完善，支持 Light/Dark 双主题
- Radix Primitives 统一引入，替换自定义实现
- Tailwind 配置与设计令牌同步

**实施步骤**:
1. 审计当前 `design-tokens.ts` 与 `index.css`，统一变量命名
2. 建立 `--color-primary`, `--color-destructive` 等语义化变量
3. 将 Tailwind `theme.extend` 全部指向 CSS 变量
4. 逐模块替换硬编码颜色值

#### A-2 组件库规范化

**目标**: 消除 260+ 处硬编码颜色，整合 A2UI 渲染器，拆分 Chat.tsx 巨型组件

**关键交付物**:
- 硬编码颜色全部替换为设计令牌引用（目标归零）
- A2UI 渲染器整合：`components/chat/A2UIRenderer.tsx` 与 `components/a2ui/core/A2UIRenderer.tsx` 合并为单一入口
- `Chat.tsx` 拆分为 ≤ 300 行/文件的独立模块（ChatHeader, ChatBody, ChatFooter, ChatState）
- 组件 Props 全部补齐 TypeScript 类型定义

**度量指标**:
```
硬编码颜色:  260+ → 0
A2UI 渲染器: 2 份  → 1 份
Chat.tsx:   800+ 行 → ≤300 行/文件（拆分为 4+ 模块）
TS any 使用: 减少 50%
```

#### A-3 后端安全加固

**目标**: 封堵 7 项 P0 安全问题

**问题清单与修复方案**:

| # | 安全问题 | 严重程度 | 修复方案 | 验证方式 |
|---|---------|---------|---------|---------|
| 1 | CORS 配置 `allow_origins=["*"]` | 严重 | 白名单模式，按环境配置 | curl 跨域测试 |
| 2 | JWT 使用硬编码密钥 | 严重 | 环境变量注入 + 密钥轮换机制 | 密钥扫描工具 |
| 3 | `DEV_MODE` 万能登录 | 严重 | 生产环境强制禁用 + 条件编译 | 生产部署验证 |
| 4 | WebSocket 无认证 | 高 | JWT Token 握手验证 | WS 连接测试 |
| 5 | SQL 注入风险点 | 高 | SQLAlchemy ORM 参数化 | SQLMap 扫描 |
| 6 | 文件上传无校验 | 高 | 类型白名单 + 大小限制 + 病毒扫描 | 恶意文件上传测试 |
| 7 | API 无速率限制 | 中 | slowapi + Redis 令牌桶 | 压力测试 |

#### A-4 权限体系基础实现

**目标**: 实现企业微信/飞书模式的 RBAC 权限体系

**角色定义（9 种）**:

| 角色 | 代号 | 权限范围 |
|------|------|---------|
| 超级管理员 | `super_admin` | 全部权限 + 系统配置 |
| 律所管理员 | `firm_admin` | 律所内部管理 + 成员管理 |
| 高级律师 | `senior_lawyer` | 案件管理 + 合同审核 + 团队分配 |
| 律师 | `lawyer` | 案件处理 + 文档编辑 + 客户沟通 |
| 律师助理 | `paralegal` | 文档管理 + 日程安排 + 基础查询 |
| 企业客户管理员 | `corp_admin` | 企业合规 + 内部用户管理 |
| 企业用户 | `corp_user` | AI 咨询 + 合同审查 + 合规自检 |
| 个人用户 | `individual` | AI 咨询 + 找律师 + 委托 |
| 访客 | `guest` | 公开内容浏览 + 注册 |

**技术实现**:
- 后端：基于 `casbin` 或自研中间件的 RBAC 模型
- 前端：`ProtectedRoute` 组件增强 + 路由级 + 按钮级权限控制
- 数据库：`users.role` 字段扩展 + `permissions` 表 + `role_permissions` 关联表

#### A-5 问题修复 + QA

**目标**: 修复 46 张截图中识别的 12 个主要问题

| 数据展示错误 | 3 | 空状态未处理、分页计算偏移 |

#### A-6 SVG 图标统一 + Lottie 动画

**目标**: 全站图标统一使用 `lucide-react`，关键交互引入 Lottie 动画

**交付物**:

- Lottie 动画用于：加载状态、AI 思考、成功/失败反馈、空状态
- `LottieIcon` 组件完善，支持懒加载动画文件

#### A-7 路由懒加载 + 代码分割

**目标**: 首屏加载时间 < 2s（4G 网络）

**实施方案**:
- 所有页面路由使用 `React.lazy` + `Suspense`
- 按路由分组 chunk：核心（Dashboard/Chat） + 业务（Cases/Contracts） + 管理（Settings/Admin）
- 第三方库分包：`echarts`、`lottie-web`、`monaco-editor` 独立 chunk
- 预加载策略：鼠标悬停导航菜单时 prefetch 目标路由

**度量指标**:
```
首屏 JS 体积:  当前 ~2MB → 目标 < 500KB
首屏加载时间:   当前 ~4s  → 目标 < 2s (4G)
Lighthouse 性能分: 目标 > 80
```

### 3.2 详细说明

#### B-1 AI 对话体验优化

**目标**: 打造差异化的 AI 法律咨询体验

**关键交付物**:

| 子项 | 说明 | 技术方案 |
|------|------|---------|
| A2UI 增强 | 动态 UI 卡片渲染更丰富的法律结构化数据 | 新增 `CaseAnalysisCard`、`LegalClauseCard`、`RiskMatrixCard` |
| 思维链可视化 | 展示 AI 分析推理过程 | `ThinkingChain` 组件优化，支持折叠/展开/时间线模式 |
| RAG 引用溯源 | AI 回答附带法条/案例出处 | 后端 RAG Pipeline 返回 `sources[]`，前端渲染引用卡片 |
| 多轮对话上下文 | 长对话不丢失上下文 | Working Memory + Episodic Memory 协同 |
| 流式输出优化 | 打字机效果 + 中间状态卡片 | SSE 分块渲染 + `StreamingMessage` 组件完善 |

#### B-2 合同签署流程

**目标**: 对接第三方电子签章平台，实现合同全生命周期管理

**对接平台**（按优先级）:
1. **e签宝** — 市场份额最大，API 文档完善
2. **法大大** — 法律行业渗透率高，备选方案

**核心流程**:
```
合同起草 → AI 审查 → 人工确认 → 发起签署 → 各方签署 → 归档存证
    ↑                                              │
    └──────────── 驳回修改 ←────────────────────────┘
```

**技术要点**:
- 签署 SDK 集成（H5 / PC 双端）
- 签署状态 Webhook 回调处理
- 合同版本管理 + 操作审计日志
- 印章管理（企业章、个人签名）

#### B-3 匿名找律师 MVP

**目标**: 实现"滴滴模式"的律师匹配 + 匿名聊天室

**用户流程**:
```
用户描述需求（文字/语音）
    ↓
AI 分析案件类型 + 复杂度 + 地域
    ↓
智能匹配 3-5 位律师（专业、评分、价格、距离）
    ↓
用户选择律师 → 进入匿名聊天室
    ↓
双方确认合作意向 → 解除匿名 → 进入委托流程
```

**技术方案**:
- 匹配算法：加权评分（专业匹配度 40% + 用户评价 25% + 响应速度 20% + 价格 15%）
- 匿名聊天：WebSocket + 临时会话 ID + 消息端到端加密
- 律师在线状态：Redis 心跳 + 推送通知

#### B-4 一键委托 + 签约 + 支付

**目标**: 从咨询到委托的闭环交易流程

**流程设计**:

| 步骤 | 用户操作 | 系统行为 |
|------|---------|---------|
| 1. 委托意向 | 点击"一键委托" | 生成委托协议草案 |
| 2. 协议确认 | 预览 + 修改条款 | 双方在线协商 |
| 3. 电子签约 | 签署委托协议 | 调用 e签宝签署 |
| 4. 支付定金 | 选择支付方式 | 微信/支付宝/银行卡 |
| 5. 服务启动 | 查看服务进度 | 律师收到委托通知 |

**支付集成**:
- 微信支付（JSAPI / Native / H5）
- 支付宝（当面付 / 手机网站）
- 资金托管模式（阶段性释放）

#### B-5 审批工作流完善

**目标**: 完善内部审批流程引擎

**支持场景**:
- 合同审批（多级审批 + 会签）
- 费用报销审批
- 案件立项审批
- 律师指派审批

**技术方案**:

- 审批模板可配置（JSON Schema）

| WebSocket 推送 | 实时 | 聊天消息、审批待办 |
| 邮件 | 分钟级 | 重要通知、日报周报 |
| 企业微信/飞书 | 秒级 | 审批通知、紧急事件 |
| 短信 | 秒级 | 验证码、关键节点提醒 |

#### B-7 企业合规管理基础模块

**目标**: 提供企业客户基础合规自检能力

**功能范围**:

### 4.2 详细说明

#### C-1 微信小程序版本

**目标**: 覆盖微信生态用户（中国法律服务主力用户群）

**技术选型**:
- 框架：Taro 3.x（React 语法复用 Web 组件逻辑）
- 状态管理：Zustand（与 Web 端保持一致）
- API 层：复用后端，小程序端适配鉴权（微信 OpenID）

**功能范围（首版）**:
- AI 法律咨询（对话界面）
- 匿名找律师 + 一键委托
- 合同拍照上传 + AI 审查
- 消息通知
- 个人中心

**不包含（首版）**:
- 合同编辑器（引导至 PC 端）
- 律所管理后台
- 知识图谱可视化

#### C-2 Docker Compose 一键私有化部署

**目标**: 企业客户可自主部署到私有服务器

**部署架构**:
```yaml
services:
  frontend:     # Nginx + React SPA
  backend:      # FastAPI + Uvicorn
  postgres:     # PostgreSQL 15+
  redis:        # Redis 7+ (缓存 + 消息队列)
  minio:        # MinIO (文件存储)
  # 可选组件
  elasticsearch:  # 全文搜索
  qdrant:         # 向量数据库
```

**交付物**:
- `docker-compose.yml` + `docker-compose.override.yml`（开发环境覆盖）
- `.env.template` 环境变量模板（含详细注释）
- `Makefile` 一键命令（`make up`, `make down`, `make backup`, `make restore`）
- 部署文档（安装、配置、升级、备份恢复）
- 健康检查端点 + Prometheus 指标暴露

**企业定制能力**:
- 自定义品牌（Logo、主题色、站点名称）
- LLM 供应商可选（OpenAI / Azure / 本地部署）
- 数据存储位置可配置
- SSL 证书自动管理（Let's Encrypt / 自签名）

#### C-3 IM 即时通讯基础

**目标**: 律师与客户、律师与律师之间的即时通讯

**功能范围**:
- 单聊 / 群聊
- 文字、图片、文件消息
- 消息已读回执
- 历史消息搜索
- 与案件/合同关联的上下文消息

**技术方案**:
- WebSocket 长连接 + Redis Pub/Sub
- 消息持久化：PostgreSQL + 消息表分区
- 文件存储：MinIO / OSS
- 离线消息推送：集成小程序 / 企业微信模板消息

#### C-4 获客系统 MVP

**目标**: 为律师和平台提供获客能力

**律师端**:
- 律师个人主页（专业领域、成功案例、用户评价）
- 律师排行榜（按专业、评分、成交量）

**用户端**:
- 律师搜索 + 筛选（地域、专业、价格区间）
- 律师对比功能
- 在线预约咨询
- 用户评价系统

#### C-5 律所内部管理模块

**目标**: 为律所提供轻量级内部管理工具

**功能范围**:
- 律师团队管理（人员、角色、分组）
- 案件分配与进度跟踪
- 工时记录与统计
- 收入报表（按律师、按案件类型、按时间）
- 知识库管理（内部案例沉淀）

#### C-6 FeatureFlags 系统

**目标**: 支持功能灰度发布、A/B 测试、按租户开关

**技术方案**:
- 自研轻量方案（PostgreSQL 存储 + Redis 缓存 + API）
- 支持维度：全局、租户级、用户级、百分比灰度

- 后端装饰器：`@feature_flag('feature_name')`

### 5.2 详细说明

#### D-1 Tauri Desktop 客户端

**目标**: 提供原生桌面体验，支持离线使用部分功能

**技术选型**: Tauri 2.x（Rust 核心 + WebView 前端）

**优势**:
- 安装包体积小（~10MB vs Electron ~150MB）
- 内存占用低（Rust 后端进程）
- 原生系统集成（通知、文件系统、托盘图标）

**桌面专属功能**:
- 本地文件批量导入 + AI 审查
- 离线合同模板编辑
- 系统托盘常驻 + 消息通知
- 本地加密存储（敏感文档不上云）

#### D-2 React Native Mobile

**目标**: iOS / Android 原生应用，补齐小程序无法覆盖的场景

**技术选型**: React Native + Expo（快速迭代）

**移动端专属功能**:
- 推送通知（APNs / FCM）
- 生物识别登录（Face ID / 指纹）
- 拍照取证（时间戳 + GPS + 区块链存证）
- 语音输入法律咨询

#### D-3 Rust Gateway 引入

**目标**: 高性能 API 网关，处理认证、限流、路由

**技术方案**:
- 基于 `axum` 或 `actix-web` 构建
- 职责：JWT 验证、速率限制、请求路由、日志聚合、WebSocket 代理
- 性能目标：单机 10K QPS，P99 延迟 < 5ms
- 与 FastAPI 后端通过内部 HTTP/gRPC 通信

**引入策略**: 灰度替换，先处理公开 API，再逐步接管内部路由

#### D-4 律师入驻平台完善

**功能扩展**:
- 律师认证流程（执业证审核、身份验证）

- 律师团队入驻（律所批量注册）

**技术要点**:

- 财务报表
