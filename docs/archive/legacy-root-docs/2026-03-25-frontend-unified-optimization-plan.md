## 一、深浅色模式修复方案

### 1.1 问题根因

项目已有完善的 CSS 变量体系（`--background`, `--foreground`, `--muted`, `--border` 等），
但 A2UI 组件层大量使用了 Tailwind 的 `zinc-*` 固定色阶（154 处），绕过了设计系统。

### 1.2 颜色迁移映射表

| 硬编码写法 (❌) | 语义化替代 (✅) | 说明 |
|----------------|---------------|------|
| `bg-white` / `bg-zinc-50` | `bg-background` | 页面/卡片背景 |
| `bg-zinc-100` / `bg-gray-100` | `bg-muted` | 次要区域背景 |
| `bg-zinc-800` / `dark:bg-zinc-800` | `bg-muted` | 深色模式下自动适配 |
| `text-zinc-700` / `text-gray-700` | `text-foreground` | 主要文字 |
| `text-zinc-500` / `text-gray-500` | `text-muted-foreground` | 次要文字 |
| `text-zinc-400` / `text-gray-400` | `text-muted-foreground/70` | 辅助文字 |
| `border-zinc-200` | `border-border` | 标准边框 |
| `border-zinc-100` / `border-zinc-700` | `border-border/50` | 轻量边框 |
| `hover:bg-zinc-100` | `hover:bg-muted` | 悬停状态 |
| `hover:bg-zinc-200` | `hover:bg-accent` | 强调悬停 |
| `divide-zinc-200` | `divide-border` | 分隔线 |
| `ring-zinc-300` | `ring-ring` | 焦点环 |

## 二、统一页面布局规范

### 2.1 标准页面容器组件

所有业务页面必须使用统一的 `PageContainer` 组件：

```tsx
<PageContainer
  title="合同管理"
  description="AI 智能审查合同，识别风险条款"
  actions={<Button>新建合同</Button>}
>
  {/* 页面内容 */}
</PageContainer>
```

### 2.2 页面组成规范

```
┌─────────────────────────────────────┐
│ PageHeader (标题 + 描述 + 操作按钮)   │
├─────────────────────────────────────┤
│ FilterBar (搜索 + 筛选 + 排序)       │ ← 可选
├─────────────────────────────────────┤
│ Content Area                         │
│ ┌─────────┐ ┌─────────┐            │
│ │  Card   │ │  Card   │            │
│ └─────────┘ └─────────┘            │
│ ┌─────────┐ ┌─────────┐            │
│ │  Card   │ │  Card   │            │
│ └─────────┘ └─────────┘            │
├─────────────────────────────────────┤
│ Pagination (分页)                    │ ← 可选
└─────────────────────────────────────┘
```

### 2.3 响应式断点规范

| 断点 | 宽度 | 页面 padding | 网格列数 | 标题大小 |
|------|------|-------------|---------|---------|
| mobile | < 640px | `p-4` | 1 列 | `text-xl` |
| tablet | 640-1023px | `p-5` | 2 列 | `text-xl` |
| desktop | ≥ 1024px | `p-6` | 2-3 列 | `text-2xl` |

## 三、功能重复清理方案

### 3.1 知识库系统合并

**现状**：Knowledge.tsx + KnowledgeBase.tsx + Search.tsx 三页重叠
**方案**：保留路由分离（符合导航结构），但统一后端 API 调用

| 路由 | 页面 | 功能范围 | 状态 |
|-----|------|--------|------|
| `/search` | Search.tsx | 混合搜索入口 | ✅ 保留 |
| `/knowledge-graph` | KnowledgeGraph.tsx | 图谱可视化 | ✅ 保留 |
| `/knowledge-base` | KnowledgeBase.tsx | 知识库管理 | ✅ 保留 |
| `/academy` | Academy.tsx | 学习中心 | ✅ 保留 |
| `/knowledge` | ~~Knowledge.tsx~~ | 重定向到 /knowledge-base | 🔄 重定向 |

### 3.2 合同模块划分

| 路由 | 导航位置 | 功能 | 说明 |
|-----|---------|------|------|
| `/contract-review` | AI 法务 > 合同审查 | 单份合同 AI 审查 | 核心 AI 功能 |
| `/contracts` | 智能协作 > 合同管理 | 合同库管理/查询 | 协作管理功能 |

**两者功能不同，保留分离，但统一上传组件。**

### 3.3 用户管理统一

| 操作 | 入口 | 权限 | API |
|------|------|------|-----|
| 修改自己信息 | /settings → 个人中心 | 所有用户 | PUT /auth/me |
| 修改密码 | /settings → 安全设置 | 所有用户 | PUT /auth/change-password |

| 角色权限管理 | /admin → 角色管理 | 仅管理员 | /admin/roles/* |

## 四、前后台权限分离方案

### 4.1 Settings 页面瘦身

**移除**：监控看板 Tab（移至 /admin/dashboard）
**保留**：个人中心、模型配置、服务集成

### 4.2 Admin 后台定位

Admin 后台是**系统运维管理界面**，功能包括：

| 模块 | 路由 | 说明 |
|------|------|------|
| 仪表盘 | /admin | 系统概览 + 监控 |
| 用户管理 | /admin/users | CRUD + 状态切换 |
| 角色管理 | /admin/roles | 权限矩阵 |
| 组织管理 | /admin/orgs | 多租户管理 |
| 审计日志 | /admin/audit | 操作追踪 |
| 系统配置 | /admin/config | 全局参数 |
| 健康监控 | /admin/health | 服务状态 |

### 4.3 权限模型

```
admin   → 前台所有功能 + 后台管理 + 后台管理入口可见
member  → 前台所有功能
viewer  → 前台只读功能
```

## 五、动效统一规范

### 5.1 动画时长标准

| 类型 | 时长 | 用途 |
|------|------|------|
| fast | 150ms | 按钮状态、hover |
| normal | 200ms | 面板展开、Tab 切换 |
| slow | 300ms | 页面过渡、模态框 |
| spring | stiffness:300 damping:30 | 卡片入场、列表动画 |

### 5.2 入场动画标准

```tsx
// 页面入场
<motion.div initial={{ opacity: 0, y: 8 }} animate={{ opacity: 1, y: 0 }} transition={{ duration: 0.2 }}>

// 卡片交错入场
<motion.div initial={{ opacity: 0, y: 12 }} animate={{ opacity: 1, y: 0 }} transition={{ delay: index * 0.05 }}>

// 弹出层
<motion.div initial={{ opacity: 0, scale: 0.95 }} animate={{ opacity: 1, scale: 1 }}>
```

### 5.3 Lottie 动画落地计划

目前 LottieIcon 组件使用 SVG 占位，需下载真实 Lottie JSON 文件存放在 `src/assets/animations/`。

### 7.2 新增优化原则

1. **所有高频法务动作优先走聊天入口**
   - 不再新增聊天页内的“跳页面型”快捷动作。
   - 交互规范统一为：预填提示词 -> 聚焦输入框 -> 用户补充 -> 发送。

2. **工作台与文档必须视为同一工作流**
   - 文档不是独立 Tab，而是工作台产物的延伸。
   - 所有“生成文书 / 查看完整文档 / 保存归档 / 新建对话”动作必须能在同一右侧面板内闭环。

3. **输入区承担上下文编排职责**
   - 输入区除文本外，还要承载附件、知识库范围、快捷动作来源等上下文。
   - 后续新增能力优先复用输入区编排，不新增平行入口。

4. **图谱交互要和主题系统完全对齐**
   - 图谱背景、标签、连线、光晕不能再使用固定深色假设。
   - 2D 和 3D 视图必须共享控制逻辑和视觉反馈标准。
