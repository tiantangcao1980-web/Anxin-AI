用户目标可拆为以下可验收交付物：

1. 使用 CLI 或 MCP 对本仓库进行代码级扫描，验证并优化 GitNexus 索引知识图，确保后续开发基于准确事实。

3. 在代码级分析之后，使用 OpenSpec 或 goal-prompt-builder 建立项目规范和验收标准。
4. 基于规范与 `/goal` 目标，从当前现状推进到商业交付：开发、测试、发布证据、回滚与风险清单完整。
5. 在宣称完成前，逐项核验文件、命令、测试、门禁和发布证据，不接受代理信号作为充分证明。
6. 2026-05-08 新增定位：把项目规范升级为中小企业双边平台 + 全设备智能助手，覆盖桌面主工作站、移动远控、任意 LLM/Skills/MCP、独立知识库和本地模型安全。
