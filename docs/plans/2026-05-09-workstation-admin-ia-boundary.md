# 工作站与治理后台信息架构边界

> 日期：2026-05-09
> 状态：执行中

## 目标

让用户清楚区分两个入口：

- **桌面工作站**：我的这台设备如何运行。
- **治理后台**：组织和平台如何被治理。

这两个入口不能成为两套重复设置页。任何新功能进入前，先判断它属于“本机运行态”还是“组织治理态”。

## 边界规则

| 维度 | 桌面工作站 | 治理后台 |
| --- | --- | --- |
| 主语 | 我、当前设备、当前运行时 | 组织、平台、管理员 |
| 数据范围 | 本机配置、只读状态、个人可用连接 | 用户、角色、组织、审计、安全、计费、系统集成 |
| 典型动作 | 切换绝密/混合/云端模式、保存本机后端地址、本地模型默认项、发送本机通知测试 | 创建用户、授权角色、配置组织级模型、管理系统集成、查看审计和系统健康 |
| 凭据原则 | 不保存 API 密钥、Token、证书；只展示可用状态或本机无密配置 | 保存和治理组织级密钥，响应必须遮罩，审计必须脱敏 |
| 失败状态 | 本机不可用、需桌面端、待签名/真机证据 | 缺外部 API、缺沙箱联调、缺审批/审计证据 |

## 交互原则

- 工作站只放“立刻影响当前桌面端”的控件。
- 工作站可以展示组织能力状态，但复杂配置跳转治理后台，不在本机页重复编辑。
- 治理后台不展示本机探针、不做本机运行模式切换。
- 相同底层 API 可以复用组件，但 UI 文案必须明确当前作用域。
- 名称避免混淆：前台为“我的设置 / 桌面工作站 / AI 连接 / 工具连接”，后台为“治理后台 / 模型治理 / 系统集成”。

## 当前落地

- 设置页标题改为“我的设置”，说明其处理个人账号、桌面工作站和当前账号可用连接。
- 工作站入口改为“桌面工作站”，面板改为“我的桌面工作站 / 本机运行配置 / 本机状态探针”。
- 后台入口改为“治理后台”，后台模型页改为“模型治理”，系统服务页改为“系统集成”。
- E2E 同步锁住新的入口文案，避免后续又退回模糊命名。

## 后续清理计划

1. 将 Settings 中会影响组织级默认值的编辑动作加作用域提示或迁移到治理后台。
2. 工作站中 MCP/知识库/LLM 只保留状态、默认本机项和跳转，不重复组织级凭据 CRUD。
3. 治理后台补“桌面工作站策略”只读汇总，避免管理员去用户的本机页找组织风险。
4. 移动端/uni-app 沿用同一规则：移动端是随身助手和审批端，不复制治理后台。
